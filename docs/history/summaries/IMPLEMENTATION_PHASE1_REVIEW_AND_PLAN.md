## 1. Codebase Review Summary

### 1.1 Objective

Before implementing the preset detection and compilation system, a comprehensive
review of the existing codebase was conducted to understand:

1. Where step types are defined and registered
2. How QE parameters are stored and used
3. How tutorial datasets are imported into Project/Calc/Steps
4. Where steps are read/written (step.yml I/O)
5. Existing test structure and patterns

### 1.2 Files Inspected

| File/Directory | Purpose | Key Findings |
|----------------|---------|--------------|
| `CONSTITUTION_ZH.md` | Project constitution | Chapter 10 defines all preset/workflow rules |
| `docs/WORKFLOW_PRESET_DESIGN_V0.md` | Design document | V0 dimensions: Spin, SOC, Material |
| `src/quantumvitas/calculation/types.py` | Step type definitions | `StepType` enum (SCF, NSCF, DOS, etc.) |

### 1.3 Key Observations

#### Step Parameters Structure
```python
# Parameters are stored as Dict[str, Dict[str, Any]]
# Outer keys are sections (CONTROL, SYSTEM, ELECTRONS, etc.)
# Inner keys are parameter names
{
    "SYSTEM": {
        "nspin": 2,
        "ecutwfc": 50,
        "occupations": "'smearing'"
    },
    "CONTROL": {
        "calculation": "scf"
    }
}
```

#### QE Parameter Defaults (from qe_module_parameters.json)
- `nspin`: default is 1 (nonspin)
- `noncolin`: default is .false.
- `lspinorb`: default is .false.
- `occupations`: no explicit default (must be specified)

#### Tutorial Datasets Available
- `tests/data/0_Si_scf/` - Silicon SCF (nonspin, insulator)
- `tests/data/8_Fe_DOS/1_collinear/` - Iron collinear (nspin=2, metal)
- `tests/data/8_Fe_DOS/2_noncolinear/` - Iron noncollinear (noncolin=.true.)
- `tests/data/6_Al_DOS/` - Aluminum (nonspin, metal with smearing)
- `tests/data/4_Si_DOS/` - Silicon DOS workflow

## 2. Constitution Analysis

### 2.1 Relevant Constitution Sections

**Chapter 10: Calculation Model & Preset/Workflow Constitution**

| Section | Rule | Implementation Impact |
|---------|------|----------------------|
| §10.1.1 | step.yml is sole executable truth | No preset persistence |
| §10.2.1 | Presets/workflows are not persistent entities | Runtime-only interpretation |
| §10.3.1 | Compiler is pure function: `compile_one(step_type, options) -> params` | No side effects, no state |
| §10.3.2 | Compiler must not depend on structure/pseudo/workflow/topology | Input-independent |
| §10.3.3 | Compiler must overwrite, not merge | Full parameter replacement |
| §10.3.4 | Compiler must use canonical encoding | Explicit all key params |
| §10.4.1 | Detector B is sole legitimate state source | No "Selected" state in UI |
| §10.4.2 | No "Selected vs Detected" dual-track model | Single source of truth |
| §10.5.1 | Single detected value or CUSTOM | No "Unknown" state |
| §10.5.3 | Detector must support implicit defaults | Handle missing params |
| §10.6.2 | `detect(compile(options)) == options` | Mathematical equivalence |

### 2.2 Derived Invariants

Based on Constitution analysis, these invariants were established:

1. **Detector B is tolerant**: Must handle QE inputs that weren't generated by Compiler
2. **Compiler is strict**: Must explicitly write all semantically relevant parameters
3. **No persistence**: Preset values exist only at runtime, never in step.yml
4. **Aggregation rule**: Multiple steps → single value (if homogeneous) or CUSTOM (if heterogeneous)
5. **Defaults**: Missing parameters interpreted per QE documentation

## 3. Original Implementation Plan

### 3.1 Milestone Structure

The implementation was planned in two major milestones:

**Milestone 1: Detector B Core Logic**
- Create module structure
- Define preset dimension enums
- Implement single-step detection
- Implement multi-step aggregation
- Add unit tests with real QE inputs

**Milestone 2: Compiler + Equivalence**
- Implement compile functions per dimension
- Implement combined compile_presets
- Add physics constraint validation
- Complete equivalence tests
- Verify mathematical invariant

### 3.2 V0 Preset Dimensions

Based on WORKFLOW_PRESET_DESIGN_V0.md, three dimensions were prioritized:

| Dimension | Options | QE Parameters |
|-----------|---------|---------------|
| Spin | nonspin, collinear, noncollinear | nspin, noncolin |
| SOC | no_soc, with_soc | lspinorb |
| Material | insulator, metal | occupations, smearing, degauss |

### 3.3 Detection Logic (Planned)

```
Spin Detection:
  if noncolin == .true. → NONCOLLINEAR
  elif nspin == 2 → COLLINEAR
  elif nspin == 4 → NONCOLLINEAR (edge case)
  else → NONSPIN (implicit default: nspin=1)

SOC Detection:
  if lspinorb == .true. → WITH_SOC
  else → NO_SOC (implicit default: .false.)

Material Detection:
  if occupations == 'smearing' → METAL
  elif occupations in (fixed, tetrahedra*) → INSULATOR
  else → INSULATOR (conservative default)
```

### 3.4 Compilation Strategy (Planned)

```
Canonical Encoding (per Constitution §10.3.4):

Spin:
  NONSPIN → nspin=1 (explicit, don't rely on default)
  COLLINEAR → nspin=2
  NONCOLLINEAR → noncolin=.true. (don't write nspin per QE docs)

SOC:
  NO_SOC → lspinorb=.false. (explicit)
  WITH_SOC → lspinorb=.true.

Material:
  INSULATOR → occupations='fixed'
  METAL → occupations='smearing', smearing='gaussian', degauss=0.01
```

## 4. Test Strategy

### 4.1 Test Categories Planned

1. **Single-step detection** - Each dimension in isolation
2. **Implicit defaults** - Missing parameters
3. **Multi-step aggregation** - Homogeneous and heterogeneous
4. **Real QE inputs** - tests/data/* tutorial cases
5. **Compiler canonical encoding** - Explicit parameter output

## 5. Assumptions and Decisions

### 5.1 Explicit Assumptions

1. **Step parameters are Dict[str, Dict[str, Any]]** - Section → params structure
2. **Section names may vary in case** - Must handle SYSTEM/system
3. **QE boolean strings** - .true./.false. or Python bool
4. **Post-processing steps** (dos, bands) don't have SYSTEM namelists from presets

### 5.2 Design Decisions

| Decision | Rationale |
|----------|-----------|
| Use enums for dimension values | Type safety, IDE support |
| CUSTOM is a singleton object | Not a string, unique identity |
| Compiler raises on invalid physics | SOC+nonspin is an error, not silent |
| validate_physics flag available | Allow bypass for edge cases |
| Post-processing returns empty | These inherit from preceding PW calc |

### 5.3 Non-Goals (Explicit Exclusions)

- **No step topology awareness** - Presets don't consider step order
- **No structure dependence** - Presets are structure-independent
- **No persistence** - Never write preset info to step.yml
- **No v1 dimensions in v0** - Accuracy, DFT+U deferred

## 6. Risk Assessment

| Risk | Mitigation |
|------|------------|
| QE default changes between versions | Rely on explicit params, test against real inputs |
| Implicit defaults misinterpreted | Extensive test coverage with edge cases |
| Physics constraints missed | Separate validation with clear errors |
| Equivalence axiom violated | Mandatory roundtrip tests |

6. ✅ No test regressions in existing unit test suite
