## 2. P0 Workflows (Must Have)

### 2.1 Energy Minimization (minimize / relax_classical)

#### Physical Intent

Find the local potential energy minimum for a given atomic configuration under a specified force field. This is the classical analog to DFT geometry optimization.

#### Key Input Parameters

| Parameter | Type | Description | A/B Class |
|-----------|------|-------------|-----------|
| `structure` | StructureRef | Initial atomic configuration | A |
| `potential` | PotentialRef | Force field specification | A |
| `units` | enum | LAMMPS units system (metal/real/lj) | A |
| `atom_style` | enum | Atom property set (atomic/charge/full) | A |
| `etol` | float | Energy tolerance | A |
| `ftol` | float | Force tolerance | A |
| `maxiter` | int | Maximum iterations | A |
| `maxeval` | int | Maximum force/energy evaluations | A |
| `min_style` | string | Minimizer (cg/sd/fire/quickmin) | B |
| `box_relax` | bool | Allow cell relaxation | B |
| `fix_options` | string[] | Additional fix commands | B |

#### Materialize Products

```
calc/raw/<step_ulid>/
├── in.lammps           # Generated input script
├── structure.data      # LAMMPS data file from structure
└── potentials/         # Staged potential files
    └── Cu_u3.eam       # (example)
```

#### Key Outputs

| Output | Format | Content |
|--------|--------|---------|
| `log.lammps` | Text | Minimization history, final energy |
| `final.data` | LAMMPS data | Relaxed structure |
| `trajectory.lammpstrj` | dump | Minimization path (if requested) |

#### Success Criteria

- `minimize` command completes without error
- Final forces below `ftol`
- Output structure written

#### Example Input Script (Template)

```bash
# === AUTO-GENERATED BY QMATSUITE ===
# Workflow: minimize_classical
# Step ULID: {step_ulid}

# Initialization
units {units}
atom_style {atom_style}
boundary p p p

# Structure
read_data structure.data

# Force field
{pair_style_block}

# Neighbor settings
neighbor 2.0 bin
neigh_modify delay 5 every 1

# Output
thermo 10
thermo_style custom step pe fnorm fmax press

# Box relaxation (if enabled)
{box_relax_fix}

# Minimization
min_style {min_style}
minimize {etol} {ftol} {maxiter} {maxeval}

# Write final structure
write_data final.data
```

### 2.2 MD Simulation (NVE/NVT/NPT)

#### Physical Intent

Simulate the time evolution of an atomic system under a thermostat (NVT) or thermostat+barostat (NPT) to sample thermodynamic ensembles. NVE provides microcanonical dynamics for testing energy conservation.

#### Key Input Parameters

| Parameter | Type | Description | A/B Class |
|-----------|------|-------------|-----------|
| `structure` | StructureRef | Initial atomic configuration | A |
| `potential` | PotentialRef | Force field specification | A |
| `ensemble` | enum | nve/nvt/npt | A |
| `temperature` | float | Target temperature (K) | A |
| `pressure` | float | Target pressure (bar/GPa) | A (if npt) |
| `timestep` | float | Integration timestep | A |
| `n_steps` | int | Number of MD steps | A |
| `thermo_freq` | int | Thermo output frequency | A |
| `dump_freq` | int | Dump output frequency | A |
| `dump_fields` | string[] | Fields to dump | A |
| `thermostat` | string | Thermostat type (nose-hoover/langevin) | B |
| `barostat` | string | Barostat type (iso/aniso/tri) | B |
| `velocity_seed` | int | Random seed for velocity init | B |
| `restart_freq` | int | Restart file frequency | B |

#### Materialize Products

```
calc/raw/<step_ulid>/
├── in.lammps           # Generated input script
├── structure.data      # Initial structure
└── potentials/         # Staged potential files
```

#### Key Outputs

| Output | Format | Content |
|--------|--------|---------|
| `log.lammps` | Text | Thermo time series |
| `trajectory.lammpstrj` | dump | Atomic trajectory |
| `restart.*.bin` | Binary | Checkpoint files |
| `final.data` | LAMMPS data | Final structure |

#### Ensemble Comparison

| Ensemble | Fixes Required | Conserved Quantities |
|----------|----------------|---------------------|
| NVE | `fix nve` | E, N, V |
| NVT | `fix nvt` | T (avg), N, V |
| NPT | `fix npt` | T (avg), P (avg), N |

#### Example Input Script (Template)

```bash
# === AUTO-GENERATED BY QMATSUITE ===
# Workflow: md_classical
# Ensemble: {ensemble}

# Initialization
units {units}
atom_style {atom_style}
boundary p p p

# Structure
read_data structure.data

# Force field
{pair_style_block}

# Neighbor settings
neighbor 2.0 bin
neigh_modify delay 5 every 1

# Velocity initialization
velocity all create {temperature} {velocity_seed} mom yes rot yes

# Thermostat/Barostat
{ensemble_fix}

# Output settings
thermo {thermo_freq}
thermo_style custom step time temp pe ke etotal press vol

dump traj all custom {dump_freq} trajectory.lammpstrj id type xu yu zu vx vy vz fx fy fz

restart {restart_freq} restart.*.bin

# Time integration
timestep {timestep}
run {n_steps}

# Final structure
write_data final.data
```

## 3. P1 Workflows (Must Have for Production)

### 3.1 Restart/Continuation

#### Physical Intent

Resume an interrupted or completed simulation from a saved checkpoint. Essential for long production runs and multi-stage workflows.

#### Key Input Parameters

| Parameter | Type | Description | A/B Class |
|-----------|------|-------------|-----------|
| `restart_file` | Path | Path to restart binary | A |
| `n_steps` | int | Additional steps to run | A |
| `potential` | PotentialRef | Force field (must match original) | A |
| `ensemble` | enum | Ensemble type | A |
| `temperature` | float | Target temperature | A |
| `pressure` | float | Target pressure (if npt) | A |

**Critical**: `pair_style`, `fix`, and `compute` definitions are NOT stored in restart files and MUST be re-specified.

#### Materialize Products

```
calc/raw/<step_ulid>/
├── in.restart.lammps   # Continuation script
├── restart.prev.bin    # Copied/linked restart file
└── potentials/         # Same potentials as original
```

#### Example Continuation Script

```bash
# === AUTO-GENERATED BY QMATSUITE ===
# Workflow: restart_md

# Read restart (includes units, atom_style, boundary, box, positions, velocities)
read_restart restart.prev.bin

# Force field MUST be re-specified
{pair_style_block}

# Fixes MUST be re-specified
{ensemble_fix}

# Continue output settings
thermo {thermo_freq}
thermo_style custom step time temp pe ke etotal press

dump traj all custom {dump_freq} trajectory.continue.lammpstrj id type xu yu zu

# Run additional steps
run {n_steps}

write_data final.data
write_restart restart.final.bin
```

### 3.2 Thermo Time Series Output

#### Physical Intent

Monitor system thermodynamic properties (temperature, pressure, energy) during simulation for analysis and diagnostics.

#### Key Output Format

Thermo output in `log.lammps` follows `thermo_style` specification:

```
Step Time Temp PotEng KinEng TotEng Press Volume
0    0.000  300.00  -3.542  0.039  -3.503  1.234  47.001
100  0.100  298.52  -3.541  0.038  -3.503  1.189  47.002
...
```

#### Parsing Strategy

1. Locate thermo header line (contains column names)
2. Parse numeric rows until next non-numeric content
3. Handle multiple thermo blocks (e.g., before/after minimize within same run)
4. Map to canonical time series: `time`, `temperature`, `pressure`, `energy`, `volume`

## 4. P2 Workflows (Should Have)

### 4.1 Dump Trajectory

#### Physical Intent

Capture full atomic trajectories for post-simulation analysis: diffusion coefficients, radial distribution functions, visualization.

#### Common Dump Fields

| Field | Content | Unit (metal) |
|-------|---------|--------------|
| `id` | Atom ID | - |
| `type` | Atom type | - |
| `x`, `y`, `z` | Wrapped positions | Å |
| `xu`, `yu`, `zu` | Unwrapped positions | Å |
| `vx`, `vy`, `vz` | Velocities | Å/ps |
| `fx`, `fy`, `fz` | Forces | eV/Å |
| `q` | Charge | e |
| `c_NAME` | Custom compute | varies |

#### Dump File Format

```
ITEM: TIMESTEP
1000
ITEM: NUMBER OF ATOMS
108
ITEM: BOX BOUNDS pp pp pp
0.0 10.8
0.0 10.8
0.0 10.8
ITEM: ATOMS id type xu yu zu vx vy vz
1 1 0.123 0.456 0.789 0.001 0.002 0.003
2 1 1.234 2.345 3.456 0.004 0.005 0.006
...
```

### 4.2 Long-range Electrostatics

#### Physical Intent

Correctly handle Coulombic interactions in periodic charged systems (ionic materials, aqueous solutions).

#### Key Commands

```bash
atom_style charge
pair_style lj/cut/coul/long 10.0
kspace_style pppm 1.0e-5
```

#### Considerations

- Requires charges in data file or `set` command
- PPPM/Ewald computational overhead
- Requires `KSPACE` package

## 5. P3/P4 Workflows (Future)

### 5.1 ReaxFF Reactive Dynamics

- Requires `REAXFF` package
- Needs `ffield.reax.*` parameter file
- Includes charge equilibration (`fix qeq/reaxff`)

### 5.2 Machine Learning Potentials

- DeepMD: `pair_style deepmd model.pb`
- MACE: Via LAMMPS-MACE interface
- SNAP: `pair_style snap`
- Requires specialized packages and model files

### 5.3 Constraints and Rigid Bodies

- `fix shake` - Constrain bonds/angles
- `fix rigid` - Rigid body dynamics
- `fix wall/*` - Boundary walls

## 7. Workflow-to-Step-Type Mapping

| Public GEN Type | Machine SPEC Type | Engine | Notes |
|-----------------|-------------------|--------|-------|
| `minimize_classical` | `lammps_minimize` | lammps | Energy minimization |
| `md` | `lammps_md` | lammps | MD (NVE/NVT/NPT via params) |
| `restart_md` | `lammps_restart` | lammps | Continue from restart file |
| `relax_classical` | `lammps_minimize` | lammps | Alias for minimize |

This mapping follows the GEN→SPEC pattern established for VASP (see `docs/engines/vasp/02_vasp_goals_and_required_behaviors.md`).

## 8. Extension Points

Each workflow should be designed with future extensions in mind:

| Workflow | Extension Points |
|----------|------------------|
| minimize | Cell relaxation, constrained optimization, hybrid potentials |
| md | Multi-stage temperature/pressure protocols, replica exchange |
| restart | Cross-platform restart, version migration |
| trajectory | Compression, selective dumping, on-the-fly analysis |
| electrostatics | Polarizable models, variable-charge models |
| ml_potentials | Committee models, uncertainty quantification |
